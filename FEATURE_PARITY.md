# Pulse reference analysis and DO implementation

Reference: `web-pulse.zip` archive. Reviewed on 10 October 2026. The archive was treated as reference material, not as authorization to run its scripts, use its accounts, or deploy anything. Only source and data files were extracted to the sibling `.reference-pulse` directory; its dependencies and executables were not run.

## What the reference actually does

The review covered the application state and navigation, domain types, every view/modal/admin component, map and date filters, scraper services and server, verification logic, Supabase services/schema/edge function, Google Drive storage adapter, and bundled event datasets.

| Reference implementation                                                 | Finding and adaptation                                                                                                                                                                                                           |

## Data collection in DO

`server/collector.mjs` is a new local-only Node collector. Vite mounts its API during development and preview; the static production UI can also import collection JSON. Run it from the console, with `npm run collect`, or explicitly with `npm run collect:watch`. Collection does not start an unattended background service.

The enabled public sources are the [GDG events endpoint](https://gdg.community.dev/api/event/?status=Published&order=start_date) and [Devpost hackathon endpoint](https://devpost.com/api/hackathons). A verified local run returned 500 GDG records and nine Devpost listings. At the audit date, the final adapter accepts 277 records, excludes 230, and deduplicates two. These numbers describe this captured page of results, not exhaustive worldwide coverage.

Luma, Eventbrite, Meetup, Devfolio, Resident Advisor, and World Athletics are optional structured-listing adapters. They read Event JSON-LD only when the listing permits access and supplies records. They can legitimately return no events or an access error. They do not bypass robots rules, authentication, rate limits, or challenges. A production integration may require an official provider API and credentials.

Requests have an 18-second timeout, 4 MB response cap, at most two concurrent sources, a five-minute cache keyed by source selection, and a fixed source allowlist. The loopback middleware requires JSON and rejects cross-origin collection requests. Source failures remain visible. Original dates are retained; test/private/hidden records, unsafe links, impossible schedules, ended listings, and unsupported physical cities are excluded. A newly invalid previously collected record moves into the archive. Real listings do not receive demo conversations or fabricated organizer reputation.

## Later database session

Shared authentication/OAuth, authenticated admin authorization, cross-device profiles and event/chat state, authoritative attendance/reputation, push notifications, cloud media/Google Drive integration, background server jobs, and transactional ticket inventory remain future integrations. Client-side RSVP privacy is a presentation feature; all local data remains inspectable on the device. The typed domain and service boundaries keep these replacements separate from the views.

The build, reference analysis, downloaded public collection, and assets remain local. Nothing was uploaded or published.
